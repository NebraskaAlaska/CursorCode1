5cHandoff specification — for the Streamlit implementation agent

Virtual LAB — handoff specification

Target: existing Python Streamlit app with working scientific backends. This spec defines presentation only — no scientific logic. Values in the mockups are SYNTHETIC DEMO placeholders; bind real backend outputs 1:1.
1 · Navigation
Persistent left sidebar, 236 px, order fixed: Home · Projects · Material Workspace · Machines · Results · Validation & Uncertainty · Evidence Library · Run History · Settings & Diagnostics — grouped under kickers OVERVIEW / RESEARCH / RIGOR / SYSTEM. Footer: current project, material ID, engine + assistant status dots, version. Active item: 2 px accent left rule + 9% accent tint. Individual scientific machines are never top-level nav — they live inside Machines. Streamlit: st.sidebar with a custom option list (or streamlit-option-menu); status footer via markdown; Lucide icons at stroke 1.5.

3 · Component inventory
Sidebar nav · top context bar · machine card · material card · result card · epistemic label · maturity badge · warning banner · science note · verification panel · missing-inputs panel · provenance panel · validation chip set · next-experiment card · stepper · mode tabs · timeline row · evidence card · stat cell · loading / empty / error states (5b). Implement each once as a Python render helper (e.g. ui.badge(kind), ui.card(...)) emitting HTML via st.markdown(unsafe_allow_html=True), backed by one injected CSS block.

6 · Spacing
Base grid ≈ 4 px: 4 / 8 / 12 / 16 / 20 / 28. Card padding 14–16 px · grid gaps 16 px · page padding 22–28 px · top bar 52 px · sidebar 236 px · right rail 340–380 px. Section rhythm inside cards: 8–10 px. Never center whole pages; content is left-anchored on a 12-col, 1440 px reference frame.
7 · Cards
Blueprint grammar: transparent background, 1 px hairline border, square corners (radius 0), four "+" registration marks at the corners (11 px, ink @ 55%). Emphasis variants: accent border (recommended actions), amber border (warnings), green border (measured), red (errors); highlight cards add a 5% accent tint. Nested sub-panels: plain hairline, no marks. Streamlit: bordered containers + injected CSS; marks via ::before/::after or an SVG corner sprite on the container class.
8 · Status badges
Three families, one shape (square, condensed caps, 2×8 px padding): Epistemic — outline = origin (USER PROVIDED, LITERATURE; SYNTHETIC DEMO is dashed amber), tint = machine output (MEASURED green, SIMULATION steel, ML PREDICTION violet, ADVISORY amber), solid green = VALIDATED AGAINST MEASURED DATA (the only filled badge); MISSING is dashed red. Maturity — READY / ACTIVE outlined green/steel; ADVISORY amber tint; *_REQUIRED neutral tint. QC — BDL neutral, blank-ratio amber, within/outside criteria green/red. A value without its badge is a bug.
9 · Buttons
Primary: accent fill, dark text, square — one per view, reserved for the main forward action (Run, Open machine). Secondary: hairline outline. Ghost: accent text only. Sizes 12–13 px, padding ~6×14. Disabled = 45% opacity — Run is always rendered disabled until its confirmation checkbox is checked. Focus: 2 px accent outline, offset 2. Hover: primary lightens one ramp step; secondary gets 7% ink tint.
10 · Forms
Inputs/selects: surface fill #141e29, hairline border, square, 36 px min-height, 14 px text; labels 12 px @ 70% ink above. Radio/checkbox: square 16 px marks (dot radius 0). Segmented control for exclusive filters. Unconfirmed defaults carry an inline amber note ("default assumed — confirm"). Units render beside the field, never inside the value. Streamlit: native widgets restyled via CSS; the confirmation gate is st.checkbox controlling the Run button's disabled prop.
11 · Tables
Headers: 11 px caps @ 60% ink, hairline underline. Rows: 12–12.5 px, hairline @ 8% between, hover 4% ink tint. Numbers mono, right-aligned; units in a dim column or the header, never appended to values. QC / verdict chips inline in the last column. BDL rendered as "< DL", never 0. Streamlit: st.dataframe column_config for plain data; HTML tables for chip columns.
12 · Warning patterns
Amber panel (border 40%, fill 10%, text #e8dcbf) = scientific caution: unconfirmed defaults, low replicates, database coverage, non-normalized sums. Steel panel = method notes and HOW-TO-VERIFY. Red is reserved for errors, missing data and out-of-criteria verdicts. Warnings never block; gates block. Every machine result repeats its warnings in the Results feed row.
13 · Empty states
Dashed hairline panel + status badge + one-line reason + one action. The reason names the missing prerequisite (TRAINED MODEL REQUIRED, "No measured XRD pattern"). Never render sample/fake content in an empty slot; never hide the section — absence is information.
14 · Error states
Red hairline panel: what failed (plain language) + what is preserved ("configuration saved — nothing was run") + Retry + Diagnostics link. Engine unavailability also downgrades the machine's card in the gallery (dot in Settings matrix). Errors never fabricate partial results.
15 · Loading states
Staged and honest: named stage ("writing selected output…"), thin determinate bar when stages are known, mono elapsed time. Skeletons only for layout-known fetches (card outlines at 10% ink). No indeterminate spinners for engine runs. Streamlit: st.status with staged updates.
16 · Responsive rules
≥1280: sidebar + main + right rail. 1100–1280: rail narrows to 300 px. <1100: sidebar collapses behind menu button (top bar appears); rail stacks under main. <820: stat grids 2-up → 1-up; tables shed tertiary columns (keep value + unit + QC); stepper compresses to numbers. Badges never truncate mid-label — wrap whole. Reference frames: 1440 (1a) and 768 (4f). In Streamlit this is the built-in sidebar collapse + column reflow.
17 · Interaction behavior
· No machine executes automatically — configure → preview → review assumptions → explicit confirmation → run, always.
· Run buttons stay visibly disabled until confirmation; the gate text is "Review and confirm simulation assumptions."
· Every displayed value carries its epistemic badge; every result panel shows assumptions, warnings, provenance, validation status, HOW TO VERIFY, and a recommended next experiment.
· Missing inputs are listed, linked and blocking where scientific — never silently defaulted (defaults that do exist are marked "assumed — confirm").
· VALIDATED appears only from the Validation machine after measured data meets criteria; simulation, ML and literature can never produce it.
· Artifacts cross-link: run → result → measurement → comparison → next experiment (see Run History 4d).
· Hovers: rows 4% tint, buttons one ramp step; keyboard focus 2 px accent ring; ::selection accent @ 30%.
